# Lighthouse (mobile): прод до и после выкатки 2026-10-25

Замеры с одной машины, Lighthouse 13.5, эмуляция Moto G Power / 4G. «До»: прод утром 2026-10-25, один прогон.
«После»: прод после деплоя (commit cbb61f2), два прогона, показан разброс. Сырые отчёты не хранятся в git
(`seo-audit/lighthouse/` в .gitignore); повторить: `npx lighthouse <url> --view`.

Что видно:
- Вес страниц упал вдвое (шрифты свои, картинки нужной ширины, gtag после загрузки), CLS почти ноль, TBT ноль на
  главной, каталоге и статье. Accessibility 96–100 (было 92–100).
- LCP на проде улучшился меньше, чем в локальном замере (локально тур 5,1 → 2,9 с). Причина в сети, а не в странице:
  каждое новое соединение до сервера в Сингапуре ~1 с, nginx отдаёт только HTTP/1.1 (`docs/SERVER.md`, пункт 1).
- Страница тура не выиграла в баллах, и часть причины в пакете A: шрифты (≈140 КБ) переехали с быстрого CDN Google на
  наш далёкий сервер, а по HTTP/1.1 их предзагрузка занимает соединения, нужные главной картинке (в замере шрифты
  приходят на 3,0 с, картинка на 4,4 с). С HTTP/2 все запросы идут по одному соединению и этот конфликт исчезает.
  Если HTTP/2 включить нельзя, запасной вариант: убрать `preload` шрифтов в шаблонах (текст покажется системным
  шрифтом на долю секунды дольше).
- Разброс между прогонами на проде до 25 баллов: для решений смотреть полевые данные (Search Console → Core Web
  Vitals), а не одиночные лабораторные замеры.
- SEO 92 в одном прогоне статьи: Lighthouse не скачал robots.txt (сбой замера), файл отдаётся 200.
