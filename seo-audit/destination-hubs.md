# Хабы направлений: дизайн данных и шаблона (фаза 3, только предложение)

Цель: по одной сильной странице на каждое место, которое люди ищут («Song-Kul lake», «Kel-Suu», «Ala-Kul trek»),
с автоматическим списком туров через это место. Хабы строятся в Astro (фаза 4); здесь схема данных, правила
подбора туров и содержимое первых девяти хабов. Цифры ниже посчитаны по текущим 79 турам (`scripts/check-sights.js`
и `seo-audit/sights-mismatch.csv`).

## 1. Адрес: два варианта

| | `/destinations/<slug>/` | `/kyrgyzstan/<slug>/` |
|---|---|---|
| Пример | `/destinations/song-kul/` | `/kyrgyzstan/song-kul/` |
| Плюсы | Понятно, что это гид по месту, а не тур; привычный раздел у туроператоров; не привязан к стране, если позже появятся Казахстан или Узбекистан в комбинированных турах; хлебные крошки Home / Destinations / Song-Kul | Слово «kyrgyzstan» в каждом URL и крошках, совпадает с формой запросов («kyrgyzstan song kul lake»); естественный родитель `/kyrgyzstan/` как обзорная страница страны |
| Минусы | Нет ключевого слова страны в URL (вес у этого сигнала маленький) | Если появится соседняя страна, раздел придётся дублировать; `/kyrgyzstan/` конкурирует с главной за запрос «kyrgyzstan tours» |
| Корейская версия | `/ko/destinations/song-kul/` | `/ko/kyrgyzstan/song-kul/` |

**Рекомендация: `/destinations/<slug>/`.** Главная уже занимает запрос «Kyrgyzstan tours», а хабы отвечают на запросы
про места; раздел переживёт расширение географии без переездов и 301. Если вам важнее слово в адресе, второй
вариант равноценен технически, решение не влияет на схему данных ниже.

## 2. Схема данных (`content/destinations.json`, правит бот или файл; в Astro это коллекция с zod)

```ts
{
  slug: 'song-kul',                       // адрес, не меняется
  name: 'Song-Kul Lake',                  // H1
  spellings: ['Song-Kul', 'Song-Kol', 'Son-Kul', 'Сонкёль'],   // для подбора туров и поиска по сайту
  type: 'lake' | 'valley' | 'town' | 'gorge' | 'pass' | 'monument' | 'region',
  region: 'Naryn',
  title: 'Song-Kul Lake, Kyrgyzstan: Horse Treks, Yurt Stays & How to Get There',   // ≤60 после обрезки брендом
  metaDescription: '...',                 // ≤155
  intro: 'markdown',                      // 2–3 абзаца от владельца или из статьи блога
  facts: {                                // показываются как factbar, пустые скрываются
    altitude: '3,016 m',                  // TODO(owner): проверить, в данных туров только высота ночёвок (Yurt 3100 m)
    bestSeason: 'June to September',      // можно вывести из сезонов туров через это место
    distanceFromBishkek: '300 km, 5–6 h', // TODO(owner)
    stay: 'yurt camps of herder families' // из текстов туров
  },
  howToGetThere: 'markdown',              // TODO(owner) или из блога
  map: { lat: 41.84, lng: 75.13, zoom: 10 },   // координаты уже есть в places[] туров
  cover: 'img/places/song-kol.jpg', gallery: ['img/catalog/…'],   // есть в content/sights.json и public/img/places
  tourMatch: {                            // правило автосписка туров, см. §3
    patterns: ['Song[-\\s]?K[ou]l'],      // по умолчанию строятся из spellings
    pin: ['song-kul-horse-trek-3-days'],  // всегда первыми, вручную
    exclude: []                           // тур, который формально упоминает место, но туда не ведёт
  },
  relatedPosts: ['yurt-culture-etiquette', 'best-time-to-visit-kyrgyzstan'],
  relatedDestinations: ['kyzart', 'kochkor', 'issyk-kul'],
  faq: [{ q: '...', a: '...' }],          // видимые, они же в FAQPage; без выдумок: из фактов туров
  updatedAt: '2026-10-25'
}
```

Проверки при сборке (warning, не ошибка): хаб без единого тура; хаб без intro; тур, у которого места в `places[]`
нет ни в одном хабе; хаб, на который не ссылается ни одна страница.

## 3. Как хаб собирает список туров

Три источника, по убыванию надёжности:
1. **`pin`** (ручной список) идёт первым, в заданном порядке.
2. **Место в `places[]` тура** (то, что сейчас показано в «Sights visited»): надёжно, после миграции фазы 1 там нет
   лишних мест.
3. **Название места в заголовке дня или в поле ночёвки** (`itinerary[].title`, `overnight`): ловит туры, у которых
   `places[]` неполон (177 строк «упомянуто, но не показано» в `sights-mismatch.csv` закрываются именно этим).

Упоминание только в описании дня в список не попадает (часто это «вид на Иссык-Куль с перевала»). Если такие туры
нужны, их добавляют через `pin`. Исключения через `exclude`.

Сортировка внутри хаба: закреплённые → туры, где место является ночёвкой или стоит в названии тура → остальные;
внутри группы короткие впереди (для хаба про место люди чаще ищут короткие поездки). Карточки те же, что в каталоге.

## 5. Шаблон страницы хаба (сверху вниз)

1. Hero: фото, H1, одна строка «Naryn region · 3,016 m · June to September · 300 km from Bishkek» (из `facts`,
   пустое не показывается), крошки Home / Destinations / Song-Kul.
2. Intro (2–3 абзаца) + «How to get there» (сворачиваемый блок на телефоне).
3. **Tours that go to Song-Kul**: карточки, те же фильтры-чипы по длительности (1 день / 2–4 / 5–7 / 8+), счётчик.
4. Карта: один маркер хаба + маркеры мест из `relatedDestinations` (статичная картинка или лёгкая карта без
   тяжёлых библиотек; в Astro можно статичный тайл с пином).
5. «Read before you go»: статьи из `relatedPosts`.
6. FAQ (видимый + `FAQPage`): «How many days do I need?», «Can beginners ride to Song-Kul?», «When is the lake
   open?»: ответы собираются из фактов туров (мин./макс. длительность, сезон, формулировки из FAQ туров).
7. Форма заявки (тот же `#leadForm`, скрытое поле `tour = "Destination: Song-Kul"`).
8. «Nearby»: другие хабы.

JSON-LD: `TouristDestination` (name, description, geo, image, touristType, includesAttraction при наличии) +
`BreadcrumbList` + `FAQPage` + `ItemList` туров. Без рейтингов.

## 6. Перелинковка после запуска хабов

- Карточки «Sights visited on this tour» на странице тура становятся ссылками на хабы (сейчас это картинки без ссылок).
- Must-see на главной ведёт на хабы вместо временных туров.
- В каталоге фильтр «Destination» (чипы = хабы) и ссылка на хаб из активного фильтра.
- Статьи ссылаются на хабы по упоминанию (ala-kol-trek-guide → ala-kul, karakol, altyn-arashan).
- Футер: колонка «Destinations» с 6–9 ссылками (это добавление элементов, нужно ваше «да»).
- Sitemap: `sitemap-destinations.xml` в индексе (фаза 4).
