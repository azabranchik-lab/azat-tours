# AZAT TOURS Car Partners Bot — техническое задание

> Лежит в `docs/car-partners/SPEC.md` проекта `kyrgyzstan-tours`. Claude Code читает его перед каждой фазой работы.
> Источник правды по функциям, полям и текстам бота. Если что-то меняется — сначала правим этот файл.
> Функция встраивается в существующий проект (сайт `server.js` + админ-бот `bot.js`), а не делается отдельным сервисом.

---

## 1. Цель

Telegram-бот, через который местные партнёры (владельцы авто и прокатные компании Кыргызстана)
размещают свои автомобили для аренды на сайте AZAT TOURS (azattours.com).

- Партнёр **регистрируется один раз** (имя, телефон, город, согласие с условиями).
- Дальше добавляет **любое количество авто**, каждое — пошаговым мастером с кнопками.
- Фото загружаются прямо с телефона, по заданным ракурсам.
- AZAT TOURS **модерирует** каждое авто в админ-группе; при одобрении описание автоматически переводится
  на английский (Claude), админ может поправить перевод, затем авто публикуется.
- Сайт получает одобренные авто через сгенерированный файл **`public/cars-data.js`** (`window.CARS`),
  так же, как туры получают `tours-data.js`.
- Клиент бронирует авто через **форму заявки** на сайте (как у туров); заявка приходит владельцу AZAT TOURS.
  Контакты партнёра на сайте не показываются.
- Комиссия AZAT TOURS — **15% сверху** цены партнёра: клиент платит цену партнёра + 15%, партнёр получает свою
  цену целиком. Размещение бесплатное.

Язык бота (партнёр и админ): **только русский** в первой версии. Кыргызский добавим позже: все тексты идут через
i18n, колонка KY в разделе 9 — задел на будущее, сейчас не используется. Сайт — на английском.

## 2. Стек (как в остальном проекте)

| Что | Чем |
|---|---|
| Рантайм | Node.js (версия на VPS — см. ниже), **JavaScript, CommonJS**, без сборки |
| Бот | grammY, long polling, **отдельный токен** (отдельный бот для партнёров), запускается из `start.js` в том же процессе, что сайт и админ-бот. Плагин `@grammyjs/auto-retry` — по необходимости |
| БД | **SQLite**, один файл `content/partners.db` (вне `public/`, `content/` в `.gitignore` и не входит в деплой-архив). Драйвер: встроенный `node:sqlite`, если на VPS Node ≥ 22.13; иначе `better-sqlite3`. Доступ только через `partners/db.js`, чтобы драйвер можно было сменить в одном месте |
| Миграции | SQL-файлы `partners/migrations/NNN-*.sql`, версия в `PRAGMA user_version`, применяются при старте процесса |
| HTTP | Существующий `server.js` (модуль `http`): отдача фото авто и приём заявок. Fastify и отдельный порт не нужны |
| Фото | `sharp` (перенести из devDependencies в dependencies); проверка формата (JPEG/PNG/WebP) и размера, хранение в WebP в `content/car-photos/` через интерфейс `StorageDriver` (`save`, `delete`, `publicUrl`), первая реализация — локальная папка |
| Перевод | Claude через существующий `lib/ai.js` (ключ `anthropicApiKey` из `config.json`) |
| Валидация | собственные функции в `partners/lib/validators.js` (без zod) |
| Логи | `console` → логи pm2 (`logs/`) |
| Экспорт | CSV (UTF-8 с BOM, открывается в Excel) |
| Тесты | встроенный `node:test` (`npm test`) |
| Запуск | существующий pm2-процесс (`ecosystem.config.js`), без Docker |

Хранилище фото сделано через интерфейс `StorageDriver`, чтобы позже можно было без переписывания перейти на S3 / Cloudflare R2.

**Состояние мастера хранится в БД**, не в памяти. Бот может перезапуститься в любой момент, партнёр продолжает с того же шага.

**Бэкап:** один файл. Команда `npm run backup-partners` делает `VACUUM INTO 'backups/partners-YYYY-MM-DD.db'`
(консистентная копия даже при включённом WAL). Фото бэкапятся копированием папки `content/car-photos/`.
Бэкапы хранятся **не на том же диске** (скачиваются к себе): на сервере всего 25 ГБ. На сервере хранится только последний бэкап БД.

## 3. Настройки (`config.json`, в git не коммитится; пример — `config.example.json`)

Секреты и настройки — в существующем `config.json`, в отдельном блоке `partners`. Переменные окружения
(`PARTNER_BOT_TOKEN`) имеют приоритет над файлом.

```json
{
  "token": "…",
  "ownerId": 913187557,
  "anthropicApiKey": "…",
  "somToUsdRate": 87.5,
  "partners": {
    "token": "",
    "adminChatId": -100…,
    "adminIds": [],
    "commissionPercent": 15,
    "offerVersion": "2026-09",
    "supportWhatsapp": "+996502888001",
    "photoMaxMb": 10,
    "minFreeDiskGb": 3
  }
}
```

- `somToUsdRate` — сколько сомов в 1 USD.
- Админы = `ownerId` + `partners.adminIds`. Сейчас админ один — владелец, `adminIds` пустой.
- Если `partners.token` не задан — партнёрский бот не стартует (сайт и админ-бот работают как раньше), в лог пишется предупреждение.
- Остальные значения проверяются при старте партнёрского бота; при ошибке он не стартует и пишет понятное сообщение в лог,
  **не роняя** сайт и админ-бот.

## 5. Роли

- **Партнёр** — любой пользователь партнёрского бота, прошедший регистрацию.
- **Админ** — `ownerId` из `config.json` и пользователи из `partners.adminIds` (сейчас только владелец).
  Только админ может нажимать кнопки модерации и вызывать админ-команды. Если кнопку нажал не админ — alert «Нет доступа».
- **Админ-группа** — группа `partners.adminChatId`, куда партнёрский бот присылает новые авто на проверку и уведомления об ошибках.
- Существующий админ-бот (`bot.js`) функцию не обслуживает; в него приходят только заявки на аренду с сайта (§7).

## 6. Сценарии

### 6.1 `/start` и регистрация

1. Новый пользователь → сразу приветствие (текст `welcome`). Выбора языка в первой версии нет.
2. Шаги регистрации:
   1. **Имя или название компании** — текст, 2–100 символов.
   2. **Телефон** — reply-кнопка `request_contact` («Отправить мой номер») или ввод вручную.
      Принимаем только свой контакт (`contact.user_id === from.id`) или номер, введённый текстом. Нормализуем.
   3. **Город** — кнопки: Бишкек, Каракол, Чолпон-Ата, Ош, Нарын, «Другой город» → ввод текстом.
   4. **Условия** (текст `offer`) — кнопки «Принимаю» / «Есть вопросы» (ссылка `https://wa.me/<supportWhatsapp>`).
      При принятии сохраняем `offerAcceptedAt` и `offerVersion`.
3. Показываем главное меню.

Зарегистрированный пользователь на `/start` сразу получает главное меню.

### 6.2 Главное меню (reply-клавиатура)

`Добавить авто` · `Мои авто` · `Профиль` · `Помощь`

### 6.3 Добавление авто

Перед мастером:
- Если есть авто в статусе `DRAFT` → «Есть незаконченная анкета: {car}. Продолжить?» [Продолжить] [Начать заново].
- Если у партнёра уже есть хотя бы одно авто → «Скопировать данные из существующего авто?»
  [Новое авто] + до 5 кнопок «Копия: Toyota Camry 2019». Копия переносит все поля, **кроме** госномера, цвета,
  пробега и фото. Затем мастер спрашивает только: цвет → госномер → пробег → фото → сводка
  (в сводке можно изменить любое поле). Это главный способ быстро добавить парк однотипных машин.

Каждый шаг мастера:
- Вопрос + inline-кнопки для вариантов.
- Под вопросом кнопки: «Назад», «Пропустить» (только для необязательных), «Отмена» (черновик сохраняется).
- Ответ сразу пишется в черновик `Car` (status `DRAFT`) и в `Partner.state.step`.
- Неверный ввод → короткое сообщение об ошибке и тот же вопрос.

### 6.4 Фото

**Госномер на фото (решение владельца 2026-09-29: пусть выбирает партнёр).** Перед фото бот спрашивает, как быть
с номером на снимках спереди и сзади:
- `HIDE` «Сниму так, чтобы номера не было видно» — к фото спереди/сзади добавляется подсказка снимать чуть сбоку
  или закрыть номер; при модерации админ видит пометку и отклоняет, если номер виден;
- `BLUR` «Замажьте номер за меня» — в карточке модерации пометка «нужно замазать номер» и кнопка «Заменить фото»:
  админ присылает отредактированный снимок ответом, бот ставит его вместо оригинала (фаза 4);
- `SHOW` «Номер можно показывать» — фото публикуются как есть, выбор хранится в БД.
Прошлый выбор партнёра идёт первой кнопкой, в вопросе строка «В прошлый раз вы выбрали: …».

Обязательные ракурсы по порядку: `FRONT`, `BACK`, `LEFT`, `RIGHT`, `INTERIOR_FRONT`, `INTERIOR_BACK`, `TRUNK`, `DASHBOARD`.

- Бот просит по одному: «Фото 3/8: слева» + подсказка «Снимайте днём, авто целиком в кадре».
- Первым сообщением шага подсказка: можно отправить **все 8 фото одним альбомом** в указанном порядке.
  Если пришёл альбом (`media_group_id`) — собираем все фото альбома (дебаунс ~1.5 с, в памяти процесса), раскладываем по
  следующим незаполненным ракурсам по порядку и пишем, какие ракурсы заполнены.
**Проверка формата и размера (до скачивания и после):**
- Принимаем только JPEG, PNG и WebP:
  - `photo` (Telegram всегда присылает его как JPEG; берём самый большой размер);
  - `document` с mime `image/jpeg`, `image/png`, `image/webp`.
- Всё остальное (HEIC/HEIF, GIF, видео, PDF, прочие файлы) **не скачиваем**: отвечаем `photo_format`.
- Лимит входящего файла — **10 МБ** (`partners.photoMaxMb`). Проверяется по `file_size` из Telegram **до скачивания**;
  больше лимита → `photo_too_big`, файл не скачивается.
- После скачивания sharp читает метаданные: если реальный формат не jpeg/png/webp (подделанное расширение или mime) → `photo_format`,
  файл удаляется.
- Если короткая сторона < 600 px → `photo_small`.

**Хранение (сервер, папка `content/car-photos/`):**
- Всё сохраняется в **WebP**, оригинал не храним. Поворот по EXIF, метаданные (EXIF, GPS) удаляются.
- Основное фото: до 1600 px по длинной стороне, quality 80. Если результат больше 1 МБ — пережимаем с quality 70.
- Превью: 480 px, quality 75.
- Путь: `{carId}/{angle}-{uuid}.webp` и `...-thumb.webp`.
- Ориентир по месту: ~250–400 КБ на фото с превью, до 13 фото на авто → **около 3–5 МБ на авто** (1000 авто ≈ 5 ГБ).

**Защита диска (на сервере 25 ГБ):**
- Перед сохранением проверяем свободное место (`fs.statfsSync`). Если свободно меньше **3 ГБ** (`partners.minFreeDiskGb`):
  фото не принимаем, партнёру — `photo_unavailable`, в админ-группу — одно предупреждение (не чаще раза в час).
- Заменённое фото удаляется с диска сразу.
- «Удалить черновик» удаляет и его фото.
- Фото авто в статусе `ARCHIVED` удаляются через 30 дней.
- Черновики без изменений дольше 90 дней удаляются вместе с фото.
- Раз в сутки задача в процессе делает эту очистку и пишет в лог, сколько места занимают фото.
- `/stats` показывает размер папки `content/car-photos/` и свободное место на диске.
- Потом необязательные дополнительные фото (`EXTRA`) до 5 штук, кнопка «Готово».
- Из сводки можно заменить фото любого ракурса.

### 6.5 Сводка и отправка

- Альбом с фото + текстовая карточка со всеми полями (на языке партнёра, с человеческими названиями enum).
- Кнопки: «Отправить на проверку», «Изменить», «Удалить черновик».
- «Изменить» → список полей кнопками → выбранный шаг мастера (один) → снова сводка.
- «Отправить» → проверка, что все обязательные поля и 8 фото на месте → `status = PENDING`, `submittedAt`,
  сообщение партнёру (`submitted`), публикация в админ-группу (6.6).

### 6.6 Модерация (админ-группа)

- Сообщение: альбом + карточка на русском, включая: партнёр (имя, телефон ссылкой `tel:`, @username),
  город, госномер, все поля, ID авто.
- В карточке — выбор партнёра про номер на фото (`plateOnPhotos`); для `BLUR` кнопка «Заменить фото» (см. 6.4).
- Кнопки: [Одобрить] [Отклонить].
- «Одобрить» → бот переводит на английский текстовые поля (`description`, `color`, `longTermDiscount`,
  `driverRequirements`, `restrictions`, `availabilityNote`) через Claude, сохраняет в `en` и показывает перевод в группе
  с кнопками [Опубликовать] [Изменить перевод]. Статус пока остаётся `PENDING`.
  - «Изменить перевод» → бот просит ответить на сообщение исправленным текстом описания (ForceReply); прочие поля — кнопками по одному.
  - Если Claude недоступен или вернул ошибку → бот сообщает об этом и сразу просит ввести перевод описания вручную.
  - «Опубликовать» → `APPROVED`, `approvedAt`, запись в `ModerationLog`, пересборка `public/cars-data.js`,
    уведомление партнёру (`approved`), карточка в группе редактируется: «Опубликовано — {админ}, {время}», кнопки убираются.
- «Отклонить» → бот просит админа ответить на сообщение причиной (ForceReply). Причина сохраняется в
  `rejectReason`, `REJECTED`, лог, уведомление партнёру с причиной и кнопкой «Исправить».
  Партнёр исправляет через сводку и отправляет снова → `PENDING`.
- Повторное нажатие на уже обработанную карточку — alert «Уже обработано».

### 6.7 «Мои авто»

- Список inline-кнопками: «Toyota Camry 2019 · Опубликовано». По 8 на страницу, пагинация.
- Меню авто:
  - «Изменить цену» — применяется сразу, без повторной модерации (пересборка `cars-data.js`).
  - «Свободно / Занято» — переключает `availability`, сразу.
  - «Пауза / Вернуть на сайт» — `PAUSED` ↔ `APPROVED`, сразу.
  - «Редактировать» — любое другое поле или фото; для опубликованного авто после изменения
    статус становится `PENDING` (авто скрывается с сайта до повторного одобрения, партнёра об этом предупреждаем).
    При повторном одобрении перевод делается заново.
  - «Сделать копию» — запускает мастер копирования (6.3).
  - «Удалить» — подтверждение → `ARCHIVED` (мягкое удаление).

## 7. Сайт

### 7.1 Данные для сайта: `public/cars-data.js`

API-ключей и отдельного API нет. После каждого изменения, влияющего на сайт (публикация, пауза, возврат, архив,
смена цены, «свободно/занято», повторная модерация), `partners/site/carsData.js` пересобирает `public/cars-data.js`
(`window.CARS = [...]`) атомарно (`lib/fsx.js`). Файл также пересобирается `npm run regen` (при смене курса).

- В файл попадают только авто со статусом `APPROVED`, сортировка по `approvedAt desc`.
- Только публичные поля (таблица в разделе 4), текстовые поля — из `en`, плюс:
  - `priceSelfDriveUsd`, `priceWithDriverUsd` = `ceil(цена_партнёра × (1 + commissionPercent/100) / somToUsdRate)` — цена для клиента за сутки;
  - `depositUsd` = `ceil(deposit / somToUsdRate)` (без комиссии);
  - `photos: [{ angle, url, thumbUrl }]`.
- **Никогда не отдаём:** госномер, данные партнёра (имя, телефон, telegram), причины отклонения, оригинальные тексты,
  цены партнёра в сомах, `partnerId`. Тест проверяет это на уровне сгенерированного файла.

### 7.2 Фото на сайте

Фото хранятся вне `public/` (`content/car-photos/`). `server.js` отдаёт их по адресу `/car-photos/{carId}/{file}`
**только если авто сейчас `APPROVED`**; иначе 404. Так черновики, отклонённые и снятые с публикации авто недоступны по прямой ссылке.
Кеширование — как у остальных картинок, с защитой от выхода за пределы папки.

### 7.3 Страницы и бронирование

- Пункт меню **«Car rental»** в шапке и футере (`nav.js`).
- Страница каталога `cars.html` (фильтры: город, тип кузова, с водителем / без, мест от) и карточка авто `car.html?id=`.
- Кнопка бронирования открывает форму заявки, как у туров (`POST /api/lead` с полем `carId`, даты, формат аренды).
  Заявка приходит владельцу в существующий админ-бот; в уведомлении — авто, цена партнёра и контакты партнёра (из БД),
  чтобы владелец связался с ним. Клиенту контакты партнёра не показываются.
- **Дизайн:** в фазе 7 сначала макет по правилам `CLAUDE.md` (Soft Alpine, 375 px first), код страниц — только после «да» владельца.

## 8. Нефункциональные требования

- Все тексты бота — только через i18n (`partners/i18n/ru.js`; `ky.js` появится позже). Функция `t(key)` берёт
  текст по языку партнёра, сейчас всегда `ru`. Тест проверяет, что каждый ключ, используемый в коде, есть в `ru.js`.
- `callback_data` ≤ 64 байт, формат `scope:action:id`, например `mod:ok:abc123`.
- Обработчики идемпотентны: повторный клик не ломает данные.
- `bot.catch`: лог в консоль (pm2), пользователю — `error_generic`, в админ-группу — краткое уведомление (без токенов и персональных данных).
  Ошибка партнёрского бота не должна ронять сайт и админ-бот.
- Простой rate limit: не больше 60 апдейтов в минуту на пользователя (`partners.rateLimitPerMin`). 30 мало: быстрое
  прохождение мастера кнопками само по себе даёт около 30 нажатий в минуту.
- Заблокированный партнёр (`BLOCKED`) получает `blocked` и больше ничего.
- Миграции применяются при старте процесса.
- Тесты (`node:test`, папка `tests/partners/`): валидаторы, нормализация телефона и номера, переходы мастера (логика выбора
  следующего шага — чистые функции), расчёт цены в USD, проверка фото (формат по mime и по содержимому, лимит МБ,
  маленькое фото), выбор файлов для очистки, отсутствие приватных полей в `cars-data.js`, наличие всех ключей i18n в `ru.js`.

Предлагаемая структура:
