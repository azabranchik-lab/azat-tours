# Azat Tours — состояние проекта (передача дел)

Этот файл — чтобы в **новом чате** мгновенно продолжить работу. Покажи ассистенту папку
`C:\Users\user\kyrgyzstan-tours` и этот файл — он подхватит контекст.

## СТАТУС: проект РАЗВЁРНУТ на VPS (сайт + бот работают онлайн)
- Источник правды для **кода/дизайна** — локальная папка `C:\Users\user\kyrgyzstan-tours`. Правим здесь, потом обновляем сервер.
- Источник правды для **контента** (туры, блог, отзывы, гиды, фото, заявки, чаты) — **сервер**:
  владелец редактирует его через Telegram-бота вживую. Эти файлы (`content/*.json`, `images/`)
  на сервере новее локальных — поэтому при обновлении сервера их НЕ трогаем.

## Как продолжить в НОВОМ чате
1. Открой новый чат Claude Code на этом же компьютере (доступ к той же папке).
2. Первое сообщение: «Продолжаем проект Azat Tours, прочитай `PROJECT-STATE.md` в `C:\Users\user\kyrgyzstan-tours`».
3. Скажи, что нужно: правка кода/дизайна (→ переразвернуть) или контент (→ через бота, без деплоя).

## Как выкатить изменения кода на сервер (после правок локально)
1. Пересобрать архив, ИСКЛЮЧАЯ серверные данные:
   `tar --exclude=kyrgyzstan-tours/node_modules --exclude=kyrgyzstan-tours/config.json --exclude=kyrgyzstan-tours/content --exclude=kyrgyzstan-tours/images -czf alatoo-update.tar.gz kyrgyzstan-tours`
2. Передать другу/на сервер, распаковать поверх (content/ и images/ на сервере сохранятся).
3. На сервере: `npm install` (если менялись зависимости) → `pm2 restart alatoo`.
- Бот работает только на сервере. Локально его НЕ запускать с тем же токеном (конфликт polling).
- Для локального предпросмотра дизайна достаточно `node server.js` (сайт без бота).

## Сессия 2026-07-23 (бот, Пакет A) — надёжность данных Telegram-админки

Провёл полный аудит бота (2 разведоси: UX + надёжность данных; отчёт в истории/плане
`~/.claude/plans/cozy-toasting-twilight.md`). Владелец выбрал начать с **Пакета A — «не терять данные и
заявки»** (чистая надёжность, UX бота не меняется). Реализованы 4 фикса. Проверка — офлайн (бота локально
НЕ запускать: прод-токен → конфликт polling).

- **B1 — экранирование (чинил ЖИВОЙ баг).** Бот слал сообщения с `parse_mode:'Markdown'` и вставлял сырой
  текст посетителя (`leadsText`/`chatsText`) — символ `*`/`_`/`` ` `` в форме/чате ронял сообщение (Telegram
  400) → владелец переставал видеть заявки и чаты. Переведён на **`parse_mode:'HTML'` + `esc()`** (как в
  server.js): все `*x*`→`<b>`, `` `x` ``→`<code>`, `_x_`→`<i>`, и каждое динамическое значение обёрнуто в
  `esc()` (имена/тексты/ввод посетителя). Хелперы `esc`/`b()`/`code()` вверху `bot.js`. Проверено юнитом:
  враждебный ввод (`& < > * _ [ \``) больше не даёт «голых» угловых скобок — Telegram HTML принимает.
- **B2 — атомарная запись + бэкап.** Новый `lib/fsx.js` `writeFileAtomic()`: пишет `path.tmp` → `renameSync`
  (атомарно), сохраняя `.bak` предыдущей версии. Заменил ВСЕ прямые `fs.writeFileSync` в `lib/content.js`
  (10 шт) и `lib/store.js`. Убирает риск: краш посреди записи → битый JSON → следующая правка ботом обнуляет
  каталог. `*.bak`/`*.tmp` добавлены в `.gitignore`. Проверено: файл=new, `.bak`=old, `.tmp` удалён.
- **B3 — гонка фото (lost update).** Фото-хендлеры делали `load → await downloadPhoto → mutate → save` — во
  время `await` другой хендлер успевал свой save, правка терялась. Переписал: **скачивание ДО load**, затем
  синхронный `load→mutate→save` без `await` между (в одном event-loop интерливинг невозможен). Добавлены
  guard'ы «элемент больше не существует». Мастера (draft в памяти / load-после-download в `save*Draft`) уже
  были безопасны — логика не тронута.
- **B4 — не «молчать» при ошибке.** `bot.catch` теперь отвечает владельцу «⚠️ что-то пошло не так, последнее
  действие могло не сохраниться»; текстовый save (`editfield`) обёрнут в try/catch с явным «не удалось
  сохранить, ничего не изменено» и сбросом сессии (раньше — молчаливый провал, владелец думал, что сохранил).

## Сессия 2026-07-23 (пачка 6) — оптимизация под Safari (WebKit)

Правка совместимости (не редизайн): существующий вид теперь корректно работает в Safari (Mac + iOS).

но **финальную визуалку в Safari подтвердить владельцу на iPhone/Mac** (в Chromium `-webkit-` префиксы
просто игнорируются, поэтому регресса там нет; проверено: рендер, консоль чистая, оверфлоу нет).

- **🔴 Главное: `-webkit-backdrop-filter` добавлен ко всем 9 `backdrop-filter`.** Safari РЕНДЕРИТ блюр
  только по `-webkit-`-префиксу; без него все стеклянные/аврора-панели (шапка `header.scrolled`, `.pill`,
  `.lightbox button`, `.about-intro .cap`, `.jump-nav`, `.tour-dur`, `.steps-bar`, `.builder-nav`) в Safari
  шли БЕЗ размытия — ядро «Soft Alpine» ломалось. Плюс сброс `-webkit-backdrop-filter:none` на шаге 3
  билдера (иначе блюр «залипал» в Safari). Проверено: 9 префиксов, дублей нет, скобки сбалансированы.
- **`-webkit-text-size-adjust:100%` + `text-size-adjust:100%`** на `html` — iOS Safari перестаёт
  раздувать текст в ландшафтной ориентации.
- **`svh`-фолбэки** (паттерн `Nvh;Nsvh`) добавлены туда, где контент мог уйти под адресную строку iOS:
  `.tour-hero` (78vh desktop, 50vh mobile), `.lb-img` (lightbox 86vh), `.fs-panel` (фильтр-шторка 86vh).

  (`calc(100vh-130px)`) оставлен: на desktop Safari viewport стабилен.
- **JS проверен на Safari-убийцы:** regex lookbehind `(?<=`/`(?<!` — НЕТ (Safari<16.4 падал бы с

## Сессия 2026-07-22 (часть 2) — AVIF/WebP через серверную негоциацию

Закрыт пункт аудита 🟡 **WebP/AVIF**. Владелец выбрал направление в этом чате; пуш/деплой — отдельно.

**Подход — НЕ `<picture>`, а серверная контент-негоциация** (осознанно). Картинки ссылаются из 15+
файлов и рендерятся движками из данных (`tour-detail.js` галереи, `home-media.js` hero — хрупкий, была
ловушка с `srcset`). Переписывать каждый `<img>`→`<picture>` = широко и рискованно, задевает правило
«логику/флоу не трогать». Вместо этого — одно место в `server.js`.

- **`scripts/build-image-formats.js`** (+ `npm run build-image-formats`): идемпотентно кладёт рядом с
  каждым `.jpg/.png` в `public/img/**` два варианта — `<file>.jpg.avif` (q50) и `<file>.jpg.webp` (q80),
  через `sharp`. Имя = оригинал + расширение (не замена) → однозначный маппинг, без коллизий. Возобновляемый
  (пересобирает только устаревшие по mtime). Прогнан на всех **390** файлах → 780 вариантов, в git.
  - Вес: JPEG 48.6 МБ → **AVIF 24.2 МБ (50%)**, WebP 42.4 МБ (87%). AVIF — реальный выигрыш (~95% браузеров:
    Chrome/FF/Safari 16.4+/Edge). WebP оставлен для прослойки «webp-да/avif-нет» (владелец выбрал полное покрытие).
  - `.rotate()` НЕ вызывается: пиксели на диске уже правильно ориентированы (build-photos + загрузчик каталога
    запекли ориентацию), повторный rotate её бы сломал.
- **`server.js`** (статик-хендлер): для `.jpg/.jpeg/.png` смотрит `Accept`; если браузер поддерживает
  avif/webp и вариант есть на диске — отдаёт его (`Content-Type` варианта, `ETag`/`Last-Modified` от реально
  отданного файла, `Vary: Accept`). Нет варианта → graceful fallback на JPEG. **DOM/разметка не меняются
  вообще** — меняются только байты на проводе.
- **Проверено (curl на :5199):** avif-браузер → `image/avif` 9773 б + `Vary`; webp-only → `image/webp` 15232 б;
  `Accept:*/*` (скрейпер/старый) → `image/jpeg` 21823 б; 304 по ETag варианта; файл без варианта → jpg-фолбэк.
  `git status`: тронуты только `server.js`/`package.json`/новый скрипт + 780 картинок, **ни одного HTML/JS/CSS**.
- **Только AVIF/WebP output у sharp есть**, но sharp — devDependency → на проде его нет. Поэтому варианты в git
  (как сами jpg), а не генерятся на сервере.

- Варианты `public/img/**/*.avif|*.webp` в git → уедут с кодом через tar, серверу генерить ничего не надо.

## Как наполнять туры (метод — ВАЖНО для продолжения)
Чтобы довести остальные 38 туров до этого формата:
1. **Тексты по дням** — со страницы конкурента `kyrgyzriders.com/tours/<slug>/` (через WebFetch: title, desc, Transfer, Horse riding/Trekking, Meals, Overnight+высота, WC, Internet).
2. **Геометрия по дорогам** — **OSRM**, по сегментам:
   `https://router.project-osrm.org/route/v1/driving/{lng,lat;lng,lat}?overview=full&geometries=geojson`.
   Для каждой пары соседних точек: если `dist_km < straight·2.2 + 15` → берём геометрию OSRM (`road:true`), иначе прямой отрезок (`road:false`) — так бездорожные отроги (Kel-Suu) не уводят крюком через Ош. Складываем в `route_segments`.
3. Делалось **разовыми node-скриптами** `scripts/_*-poc.js` (уже удалены): правили `content/tours.json`, затем `require('./lib/content').regenerateDataFile()` пересобирал `tours-data.js`.
4. **СЛЕДУЮЩИЙ ШАГ:** масштабировать на 38 туров — лучше **апгрейднуть парсер `build-tours.js`**, чтобы он сразу выдавал богатый `itinerary` + `route_segments`; либо повторять per-tour скрипт. **Бот итинерарий НЕ редактирует.**
